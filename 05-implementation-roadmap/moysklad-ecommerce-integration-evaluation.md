# МойСклад И Движки Интернет-Магазинов

Дата: 2026-05-12.

## Вопрос

С каким движком интернет-магазина МойСклад лучше всего интегрирован и как это влияет на выбор платформы для нового сайта Soliton.

## Короткий Вывод

Если выбирать по критерию **готовой интеграции с минимальной разработкой**, лучший вариант сейчас выглядит так:

1. **inSales** - самый сильный готовый SaaS-вариант: современная интеграция через API, синхронизация товаров, цен, остатков, изображений и статусов заказов.
2. **1С-Битрикс** - сильный классический вариант для российского рынка: бесплатное решение от МойСклад, обмен через CommerceML, товары/остатки/заказы.
3. **WooCommerce** - рабочий вариант через платное стороннее решение, удобен если нужен WordPress.
4. **OpenCart** - рабочий вариант через стороннее решение, но слабее как стратегическая платформа.
5. **ReadyScript / Webasyst Shop-Script / AdvantShop / UMI / Tilda / uCoz** - поддерживаются через CommerceML или отдельные решения, но не являются оптимальным выбором для сложного SEO/B2B-сайта Soliton.

Если выбирать по критерию **максимальной работы через Codex**, лучший вариант остается:

**Next.js + Payload CMS + PostgreSQL + прямая интеграция с МойСклад JSON API.**

Это не самая "готовая" интеграция, но самая управляемая и гибкая для нашего проекта.

## Что Есть У МойСклад

## 1. Универсальный CommerceML-Коннектор

МойСклад пишет, что интернет-магазины, для которых нет специального подключения, можно подключить через CommerceML. В группу CML входят:

- Tilda;
- 1С-Битрикс;
- 1С-Битрикс Малый бизнес;
- AdvantShop;
- Webasyst Shop-Script;
- Nethouse;
- Simpla;
- Diafan.CMS;
- UMI.ru;
- UMI.CMS;
- Netcat;
- Magento;
- WebAsyst;
- Fast-Sales;
- uCoz.

Сценарии CommerceML:

- загрузка заказов в МойСклад;
- выгрузка остатков из МойСклад;
- передача контрагента, товаров, количества, суммы, статуса и комментария;
- резервирование товаров;
- обмен по расписанию.

## 2. JSON API

У МойСклад есть отдельный API для разработчиков. Для custom-проекта это ключевой вариант.

Через API нужно делать:

- импорт товаров;
- импорт модификаций;
- остатки;
- цены;
- заказы покупателей;
- контрагентов;
- резервы;
- статусы;
- webhooks;
- документы при необходимости.

Для Next.js/Payload это лучше, чем CommerceML, потому что интеграция будет в коде, тестируемой и расширяемой.

## Почему inSales Выглядит Лучшим По Готовой Интеграции

В каталоге МойСклад есть отдельная интеграция inSales, где заявлены:

- загрузка товаров из МойСклад в inSales;
- связывание существующих товаров;
- обновление цен, остатков и статусов заказов;
- синхронизация за минуты;
- загрузка изображений;
- пользовательские параметры;
- настройка через интерфейс;
- регулярные обновления и поддержка.

Если бы задача была "быстро запустить обычный интернет-магазин и связать с МойСклад", inSales был бы первым кандидатом.

Но для Soliton у inSales есть ограничения:

- меньше контроля над SEO-архитектурой;
- сложнее создавать нестандартные SEO-посадочные и индексируемые фильтры;
- меньше возможностей для глубокой работы Codex с кодом;
- SaaS-зависимость;
- B2B/RFQ-логика может потребовать обходов и кастомизации.

## Почему 1С-Битрикс Силен, Но Не Оптимален Для Нас

У МойСклад есть бесплатное решение для 1С-Битрикс Малый бизнес и CommerceML-интеграция для 1С-Битрикс.

Плюсы:

- знаком российским интеграторам;
- CommerceML-подход привычен;
- товары, остатки, заказы;
- можно развивать как полноценный магазин.

Минусы:

- тяжелая платформа;
- больше legacy-разработки;
- сложнее поддерживать чистую архитектуру;
- Codex сможет помогать, но скорость и качество изменений будут ниже, чем в Next.js;
- для SEO можно многое сделать, но это будет дороже и менее гибко.

## Почему WooCommerce И OpenCart Не Лучший Основной Выбор

У WooCommerce и OpenCart есть решения в каталоге МойСклад, в том числе от amgroup.

Для WooCommerce заявлены:

- синхронизация товаров;
- остатки;
- заказы;
- цены;
- статусы;
- автоматическая передача заказов в МойСклад;
- обновление остатков на сайте;
- работа через официальный API WooCommerce.

Для OpenCart заявлены:

- синхронизация товаров;
- перенос структуры каталога;
- контроль дублей;
- статусы заказов;
- остатки.

Но для Soliton это не главные кандидаты, потому что:

- SEO-архитектура и страницы будут зависеть от плагинов и шаблонов;
- меньше контроля над типами страниц и данными;
- сложнее сделать аккуратный B2B/RFQ-процесс;
- выше риск накопить смесь настроек, плагинов и кода.

## Рекомендация Для Soliton

## Если Нужен Самый Быстрый Готовый Магазин

Выбирать **inSales + МойСклад**.

Это даст быстрый старт, готовую синхронизацию и меньше разработки. Подходит, если приоритет - быстрее начать продажи и не строить собственную платформу.

## Если Нужна Российская Коробка С Интеграторами

Выбирать **1С-Битрикс + МойСклад**.

Это подходит, если компания хочет классическую российскую CMS/e-commerce-платформу, готова работать с Битрикс-разработчиками и ставит интеграции выше гибкости разработки.

## Если Нужен Лучший Сайт Для SEO И Работы Через Codex

Оставаться на **Next.js + Payload + PostgreSQL** и делать интеграцию с МойСклад напрямую через API.

Схема:

1. МойСклад - источник остатков, цен, заказов и складского учета.
2. Payload - CMS для SEO-данных, карточек, посадочных и контента.
3. Next.js - публичный сайт, каталог, карточки, фильтры, RFQ, checkout.
4. Интеграционный слой - синхронизация между сайтом и МойСклад.

## Как Интегрировать МойСклад В Нашу Архитектуру

## Поток Данных Из МойСклад На Сайт

- товары;
- артикулы;
- цены;
- остатки;
- модификации;
- изображения, если их удобно хранить в МойСклад;
- группы товаров.

Но SEO-поля лучше хранить в Payload:

- slug;
- H1;
- SEO title;
- SEO description;
- тексты категорий;
- FAQ;
- посадочные страницы;
- перелинковка;
- schema.org.

## Поток Данных С Сайта В МойСклад

- заказ покупателя;
- контрагент;
- состав заказа;
- количество;
- цена;
- комментарий;
- источник заявки;
- статус;
- резерв товара;
- реквизиты юрлица при необходимости.

## Что Должно Остаться В Payload, А Не В МойСклад

Payload должен быть центром SEO и контента:

- структура сайта;
- SEO-посадочные;
- фильтры;
- расширенные описания;
- блоки под B2B;
- FAQ;
- рекомендации;
- сравнения;
- страницы решений;
- статьи.

МойСклад должен быть центром операционного учета:

- остатки;
- цены;
- заказы;
- контрагенты;
- резервы;
- отгрузки;
- документы;
- складские операции.

## Итог

На вопрос "с чем МойСклад лучше всего интегрирован" ответ такой:

- **лучший готовый SaaS-вариант: inSales**;
- **лучший классический российский коробочный вариант: 1С-Битрикс**;
- **лучший вариант для проекта Soliton через Codex: Next.js + Payload с прямой интеграцией через МойСклад JSON API**.

Менять нашу рекомендацию по платформе из-за МойСклад не нужно. Нужно добавить в архитектуру отдельный интеграционный слой и заранее описать, какие данные принадлежат МойСклад, а какие - сайту и Payload.
