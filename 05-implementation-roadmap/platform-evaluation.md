# Выбор Платформы Для Нового Сайта Soliton

Дата: 2026-05-12.

## Задача

Нужно выбрать платформу для современного интернет-магазина и B2B-каталога Soliton, чтобы:

- максимум работ можно было делать через Codex;
- структура сайта была полностью управляемой кодом;
- можно было строить сильную SEO-архитектуру;
- был удобный каталог PDU, фильтры, карточки и документы;
- были корзина, быстрый заказ и запрос КП;
- сайт подходил и частным покупателям, и корпоративным клиентам под контракты;
- проект можно было развивать без зависимости от визуального конструктора и закрытых плагинов.

## Короткое Решение

Рекомендуемая платформа:

**Next.js + Payload CMS + PostgreSQL**

Формат магазина:

**code-first интернет-магазин с B2B-заявками и RFQ-корзиной на первом этапе.**

Если позже понадобится тяжелая e-commerce-логика: складские остатки, мультисклады, сложные цены, промо, личные кабинеты дилеров, несколько витрин, платежные сценарии и полноценный order management, можно добавить **Medusa** как commerce backend.

## Почему Это Лучший Вариант Для Работы Через Codex

## 1. Все В Коде

Codex сможет менять:

- структуру URL;
- шаблоны страниц;
- компоненты каталога;
- фильтры;
- карточки товаров;
- микроразметку;
- sitemap;
- robots;
- SEO-метаданные;
- формы;
- импорт товаров;
- генерацию посадочных страниц;
- логику корзины и запроса КП.

Это важнее, чем наличие готовой админки. Проект должен быть репозиторием, где основные решения лежат в коде и проходят через Git.

## 2. Максимальный SEO-Контроль

Next.js дает полный контроль над:

- server-side rendering;
- статической генерацией;
- динамическими metadata;
- `sitemap.xml`;
- `robots.txt`;
- JSON-LD;
- canonical;
- Open Graph;
- скоростью страниц.

Для Soliton это критично, потому что сайт должен иметь много SEO-посадочных:

- категории;
- подкатегории;
- индексируемые фильтры;
- use-case страницы;
- сравнения;
- база знаний;
- карточки товаров;
- PDF-документы.

## 3. Payload CMS Хорошо Подходит Для Каталога И Контента

Payload можно использовать как backend и CMS внутри Next.js.

В Payload нужно описать коллекции:

- товары;
- категории;
- SEO-посадочные;
- характеристики;
- документы;
- изображения;
- FAQ;
- страницы решений;
- статьи базы знаний;
- заявки;
- заказы / запросы КП.

Преимущество: схема данных описывается в TypeScript, поэтому Codex может редактировать ее напрямую.

## 4. Подходит Для B2B

Soliton не выглядит как массовый B2C-магазин с тысячами SKU. Это B2B/B2C-каталог технических изделий, где важны:

- подбор;
- КП;
- документы;
- проектные поставки;
- кастомные конфигурации;
- корпоративные заявки;
- повторные закупки;
- техническая точность.

Поэтому на первом этапе лучше не строить тяжелый marketplace/ERP-магазин. Нужен быстрый, SEO-сильный каталог с корзиной-заявкой и возможностью оформить заказ или запрос КП.

Роль:

## Hosting

Подходящие варианты:

- VPS / Docker, если нужен полный контроль.
- Railway / Render / Fly.io для простого деплоя.
- Vercel для frontend, если backend и база разнесены аккуратно.

Для российской B2B-компании часто практичнее VPS/Docker или российский облачный провайдер, чтобы не зависеть от зарубежной инфраструктуры.

## Storefront Logic

Первый этап:

- каталог;
- фильтры;
- карточки;
- сравнение товаров;
- корзина;
- запрос КП;
- быстрый заказ;
- отправка заявки менеджеру;

## Сравнение Платформ

| Платформа | Оценка Для Soliton | Плюсы | Минусы |
|---|---:|---|---|
| Next.js + Payload + PostgreSQL | 9/10 | Максимально управляется Codex, сильный SEO-контроль, современный стек, гибкая B2B-логика | Нужно разработать магазин, нет готовой коробки |
| Next.js + Medusa + CMS | 8/10 | Полноценная headless commerce-логика, товары, корзина, заказы, модули | Больше инфраструктуры, сложнее MVP |
| WordPress + WooCommerce | 6/10 | Быстрый старт, много готовых модулей, понятная админка | Много состояния в админке и плагинах, хуже для code-first работы через Codex |
| 1C-Битрикс | 5/10 | Привычен на российском рынке, 1С-интеграции, готовая коммерция | Тяжелая legacy-разработка, хуже DX, сложнее делать все через Codex |
| Shopify / Hydrogen | 5/10 | Сильная hosted commerce-платформа, Storefront API, checkout | Платформенная зависимость, ограничения checkout/B2B, спорно для российской B2B-задачи |
| Tilda / Webflow / конструкторы | 2/10 | Быстро сделать витрину | Не подходит для сложного каталога, SEO-фильтров, B2B-логики и работы через Codex |
| OpenCart / CS-Cart | 4/10 | Готовый магазин | Старее стек, много шаблонной/плагиновой логики, слабее для кастомной SEO-архитектуры |

## Почему Не WooCommerce Как Основной Выбор

WooCommerce можно использовать, если важнее быстрый запуск стандартного магазина, чем code-first архитектура.

Но для текущей задачи есть проблемы:

- много решений будет жить в админке;
- SEO-фильтры и кастомные посадочные будут зависеть от плагинов;
- массовая генерация страниц и строгая структура данных сложнее контролируются;
- Codex сможет писать PHP/темы/плагины, но проект быстрее превратится в смесь кода, настроек и плагинов.

Для Soliton лучше сделать данные и шаблоны более строгими.

## Почему Не Shopify

Shopify силен как hosted e-commerce, но задача Soliton не типичный D2C-магазин.

Ограничения:

- B2B под контракты и КП важнее обычного checkout;
- нужна сложная SEO-структура с техническими посадочными;
- нужны кастомные формы и подбор;
- российские платежи, документы и закупочные сценарии могут потребовать обходных решений;
- headless Shopify добавляет сложность и зависимость от Shopify checkout.

## Почему Не Битрикс

Битрикс понятен российскому рынку, но не лучший выбор, если цель - чтобы почти все развитие делал Codex.

Проблемы:

- тяжелая архитектура;
- много специфичных API и legacy-паттернов;
- сложнее держать проект чистым и тестируемым;
- высокая зависимость от разработчиков с опытом Битрикс;
- хуже подходит для современной компонентной SEO-архитектуры.

Битрикс имеет смысл, если обязательна глубокая 1С-интеграция с самого первого дня и компания уже живет в этой экосистеме.

## Финальная Рекомендация

Выбирать **Next.js + Payload CMS + PostgreSQL**.

Это лучший баланс для Soliton:

- достаточно гибко для SEO;
- достаточно современно для интернет-магазина;
- достаточно просто для текущего ассортимента;
- удобно развивать через Codex;
- не привязано к визуальному конструктору;
- не загоняет B2B-процесс в стандартный checkout;
- позволяет позже добавить полноценный commerce backend, если магазин вырастет.

Начинать нужно не с Medusa/Shopify/Битрикс, а с собственного code-first каталога и RFQ-магазина. Для текущей задачи Soliton это даст больше контроля и быстрее приведет к SEO-результату.

## Источники И Технические Ориентиры

- Next.js: официальная документация по [`sitemap.xml`](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap), [`robots.txt`](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/robots), metadata, JSON-LD и App Router.
- Payload CMS: официальная документация по [code-first CMS, TypeScript-конфигурации, коллекциям и API](https://payloadcms.com/docs/getting-started/what-is-payload).
- Medusa: официальная документация по [commerce modules](https://docs.medusajs.com/learn/fundamentals/modules/commerce-modules), product, cart, order и payment modules.
- WooCommerce: официальная документация по [REST API](https://developer.woocommerce.com/docs/apis/rest-api/) и Store API.
- Shopify: официальная документация по [Hydrogen](https://shopify.dev/docs/storefronts/headless/hydrogen/getting-started), headless storefront и Storefront API.

Использованы как ориентиры для выбора платформы, а не как готовая архитектура Soliton. Итоговая рекомендация учитывает специфику Soliton: технический каталог, PDU-ассортимент, B2B-заявки, запрос КП, SEO-посадочные и необходимость делать большую часть работ через Codex.
