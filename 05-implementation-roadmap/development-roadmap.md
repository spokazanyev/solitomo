# Roadmap Разработки Сайта Soliton Для Codex

Дата: 2026-05-13.

## Текущая Итерация: MVP Site Development Pass 2026-05-15

Фокус итерации:

- уменьшить смысловой шум на главной;
- сделать hero главной B2B/SEO-ориентированным, а не витриной случайного товара;
- собрать условия КП, доставки, оплаты и юрлиц в таб карточки товара;
- усилить каталог сортировкой, пустым состоянием и закрепленным фильтром;
- защитить RFQ от заявок без канала связи;
- сделать Payload dashboard полезным для владельца и подключаемого агента.

Результат зафиксирован в `07-build-specifications/mvp-site-development-pass-2026-05-15.md`.

## Принцип

Каждый этап начинается только после того, как есть минимальная спецификация. Codex может уточнять детали по ходу, но не должен строить критичные части магазина без описанных данных, сценариев и критериев приемки.

## Фаза 2A. Agent-Ready Админка И Управляемые Фильтры

Зависимости:

- `admin-configuration-spec.md`;
- `specs/016-admin-configuration-system/spec.md`;
- `product-attributes-normalization-spec.md`;
- рабочий Payload/PostgreSQL.

Работы Codex:

- улучшить `rfq-requests`: структурированные позиции вместо JSON textarea, статусы, приоритет, ответственный, комментарии, UTM/source поля;
- создать `admin-change-log`;
- добавить роли `admin`, `editor`, `sales`, `catalog_manager`, `seo`, `agent`;
- создать коллекции `filter-groups`, `filter-fields`, `filter-options`, `filter-presets`;
- сделать фильтры управляемыми из Payload: добавление, отключение, удаление, сортировка, доступность по категориям;
- обеспечить пересчет счетчиков фильтров по текущей выдаче;
- запретить автоматическое создание индексируемых URL при добавлении нового фильтра;
- добавить `agent-project-context.md` или `agent-project-context.json`;
- обновить `AGENTS.md` и `apps/web/CLAUDE.md`, чтобы Codex и Claude Code получали один и тот же контекст проекта;
- добавить scripts: `agent:context`, `export:catalog`, `validate:catalog`, `validate:seo`, `validate:schema`, `smoke:public-pages`, `agent:propose-change`, `agent:apply-change`;
- все bulk/scripts операции делать с dry-run и apply режимами.

Критерии приемки:

- админка не выглядит пустой: есть продажи, каталог, фильтры, документы, медиа, agent operations;
- новый агент может прочитать контекст проекта и понять назначение сайта, текущий статус, документы, команды и безопасный workflow;
- фильтр можно добавить или отключить через данные, без правки React-кода, если он связан с существующим controlled attribute;
- изменения агента сохраняются в audit log;
- high-risk поля требуют явного подтверждения владельца перед публикацией.

## Фаза 2B. MCP Для Агентов, Если Потребуется

Зависимости:

- стабильные Payload collections;
- готовые scripts/API для agent operations;
- понятный audit/draft workflow;
- подтвержденная потребность использовать MCP вместо прямых scripts/API.

Работы Codex:

- спроектировать локальный MCP-сервер как обертку поверх Payload API и scripts;
- добавить MCP tools: получить контекст проекта, найти товар, найти страницу, предложить изменение, создать draft, запустить проверки, получить preview, записать audit log, опубликовать после подтверждения;
- не дублировать бизнес-логику MCP-сервером: источник истины остается Payload + scripts;
- описать подключение MCP для Codex, Claude Code и других клиентов;
- добавить тесты MCP tools на локальной базе.

Критерии приемки:

- MCP не нужен для базовой работы сайта и админки;
- MCP добавляет единый интерфейс для агентов, но не обходит права, audit log и подтверждения;
- один и тот же change workflow работает через scripts и через MCP.
