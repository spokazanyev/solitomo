# Quickstart: DaData Party Autofill (063)

Как проверить фичу локально после реализации.

## Предусловия / конфиг

- `DADATA_API_KEY` задан (env или `ApiShipSettings.dadata.apiKey` — см. [client.ts:39](../../apps/web/src/lib/dadata/client.ts)). `X-Secret` для party НЕ требуется.
- Корзина не пуста (форма счёта рендерится только при наличии позиций).

```bash
pnpm --filter @soliton/web dev
# открыть страницу чекаута → выбрать «Выписать счёт» (юрлицо)
```

## Сценарий 1 — автозаполнение по названию (US1, P1)

1. В поле «Найти по названию или ИНН» ввести ≥3 символов реального названия (напр. `Сбербанк`).
2. **Ожидание**: под полем список организаций, в каждой строке название + ИНН (FR-003).
3. Выбрать строку → поля «Наименование», ИНН, КПП, ОГРН, «Юр. адрес» заполнены (FR-004). У ИП КПП пустой, без ошибки (FR-006).
4. В DevTools → Network: запрос ушёл на `/api/dadata/party`, а не на `suggestions.dadata.ru`; `Authorization` в браузере нет (FR-011).

## Сценарий 2 — автозаполнение по ИНН

1. Ввести 10 или 12 цифр реального ИНН.
2. **Ожидание**: в списке организация с этим ИНН; выбор заполняет 5 полей.

## Сценарий 3 — контроль контрольной суммы (US2, P2)

1. Ввести вручную ИНН с неверной контрольной цифрой (напр. `7707083894`).
2. **Ожидание**: под полем ошибка, кнопка «Выписать счёт» неактивна (FR-007).
3. Исправить на валидный (`7707083893`) → ошибка исчезает, кнопка активна (FR-008).
4. Ввести 9 цифр → ошибки контрольной суммы НЕТ (FR-008).

## Сценарий 4 — предупреждение о статусе (US2)

1. Выбрать через подсказку ликвидированную / банкротную организацию.
2. **Ожидание**: заметный блок-предупреждение рядом с реквизитами; кнопка остаётся активной (FR-009/SC-005). Для `REORGANIZING` предупреждения нет (Q3).

## Сценарий 5 — ручной fallback (US3, P3)

1. Ввести строку без совпадений → список пуст → все 5 полей заполняются вручную, заказ отправляется (FR-010).
2. Сымитировать недоступность: убрать `DADATA_API_KEY`, перезапустить → поле работает как текст, чекаут проходит (FR-012).

## Сценарий 6 — перевыбор (Q2)

1. Выбрать организацию A → вручную изменить «Наименование» → выбрать организацию B из подсказок.
2. **Ожидание**: все 5 полей перезаписаны данными B, включая отредактированное вручную (FR-005 exception); контроль ИНН перезапущен.

## Аналитика (FR-015)

С `NEXT_PUBLIC_ANALYTICS_DEBUG=true` в консоли / `window.dataLayer` проверить события:
- `company_suggest_shown` (`results_count`) при показе списка;
- `company_selected` (`has_kpp`, `has_legal_address`) при выборе;
- `company_status_warning` (`status`) при рисковом статусе.
Payload НЕ содержит сырых ИНН/наименования (R6).
