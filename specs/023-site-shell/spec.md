# Feature Specification: Site Shell

**Feature Branch**: `023-site-shell`

**Created**: 2026-05-15

**Status**: Draft

**Input**: Sitewide review v3 found that `SeoLandingPage` and `ProductDetailPage` each render their own header with different link sets. There is no mobile drawer. Skip-link and focus styles are missing.

## User Scenarios & Testing

### User Story 1 - Visitor Sees A Consistent Header On Every Page (Priority: P1)

A visitor opens the homepage, a catalog page, a product page and an RFQ page. The header is identical on every page: logotype, primary navigation, phone, KP CTA, RFQ cart.

**Why this priority**: Inconsistent navigation across templates damages trust and breaks IA.

**Independent Test**: SSR HTML for `/`, `/catalog/pdu/`, `/product/sp-8/`, `/b2b/request-quote/` contains the same `<header>` markup.

**Acceptance Scenarios**:

1. **Given** any public page, **When** rendered, **Then** the header markup is generated by a single `SiteHeader` component included once in the layout.
2. **Given** the contacts singleton, **When** a phone is configured, **Then** the header shows a tel: link.

### User Story 2 - Visitor Uses Mobile Drawer Navigation (Priority: P1)

A visitor on a 375px viewport taps the hamburger icon. A drawer slides in with full navigation, contacts and the KP CTA. ESC closes the drawer; focus is trapped inside while it is open.

**Why this priority**: The current `flex-wrap` header breaks on small viewports into two or three rows.

**Independent Test**: On 375px viewport, the hamburger is visible; tapping it opens a drawer with the full nav.

**Acceptance Scenarios**:

1. **Given** mobile viewport, **When** the user taps the hamburger, **Then** a drawer opens with the navigation, contacts and the KP CTA.
2. **Given** the drawer is open, **When** the user presses ESC, **Then** the drawer closes and focus returns to the trigger.

### User Story 3 - Keyboard And Screen-Reader Users Can Skip To Content (Priority: P2)

A keyboard user tabs into the page. The first focusable element is a "Skip to content" link. Activating it jumps to the main content.

**Why this priority**: Required for accessibility compliance and improves SR usability.

**Independent Test**: Lighthouse Accessibility ≥ 95 on `/` and a sampled PDP.

### Edge Cases

- What happens when contacts singleton has no primary phone? Header omits the phone link gracefully.
- What if the user is on a very wide viewport? Navigation stays single row; CTAs are always visible.

## Requirements

### Functional Requirements

- **FR-001**: System MUST render a single `SiteHeader` component included in `app/(site)/layout.tsx`.
- **FR-002**: Inline headers in `SeoLandingPage` and `ProductDetailPage` MUST be removed.
- **FR-003**: Header MUST contain logotype, primary navigation (Каталог, Подбор, Решения, Документы, Компания), phone (when available), KP CTA and RFQ cart link.
- **FR-004**: On `< md` breakpoints, the header MUST collapse to logotype, KP CTA and a hamburger trigger; navigation moves into a slide-in drawer.
- **FR-005**: Drawer MUST trap focus while open and close on ESC.
- **FR-006**: Layout MUST include a "Skip to content" link as the first focusable element.

### Key Entities

- **NavItem**: label, href, children?.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Lighthouse Accessibility ≥ 95 on `/` and one PDP.
- **SC-002**: Header HTML is byte-identical across five sampled URLs (after build).
- **SC-003**: On 375px, 768px and 1440px viewports the header behaves as specified.

## Assumptions

- Spec `018-company-contacts` exposes `getCompanyContacts()` for the header phone.
- The IA is finalised: Каталог / Подбор / Решения / Документы / Компания plus KP CTA. Adjust labels with content owner before implementation.
- Drawer is implemented without external dependencies; native `<dialog>` or simple state suffices.
