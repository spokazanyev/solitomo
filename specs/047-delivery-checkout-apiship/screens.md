# Screens: Delivery Checkout With ApiShip

**Feature**: 047-delivery-checkout-apiship

ASCII-вайрфреймы каждого экрана / формы. Назначение — фиксировать UX-контуры
для дизайнера и фронтенда. Реальная вёрстка — в `apps/web/src/components/checkout/*`
и `apps/web/src/components/admin/orders/*`.

Принципы:
- Мобильный first; на десктопе тот же контент в две колонки.
- Все строки локализованы (`adminLabel`).
- Один селектор ПВЗ для всех провайдеров (`СДЭК`, `Boxberry`, `Почта`...).

```
│   └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│ Корпус/строение  Квартира   Индекс (авто)                       │
│ [___________]    [_______]  [125009 ]                           │
│                                                                 │
│  ⓘ Адрес нормализован: KLADR 7700000000007240, FIAS …           │
└─────────────────────────────────────────────────────────────────┘
```

Поведение:
- Подсказки появляются через debounce 300 мс, **server-side proxy** `/api/shipping/validate-address?suggest=1`.
- Выбор подсказки заполняет все поля (улица, дом, индекс, координаты).
- Если DaData недоступен (degraded) — поле остаётся ручным, индекс — обязательный.
- Все нормализованные данные сохраняются в `Order.delivery.addressNormalized` для будущей сверки.

## S13a. Retry payment (FR-111)

```
│ │ Доставка:           1 250 ₽    СДЭК · до двери           │   │
```
