## REST endpoints

Все через стандартный Payload REST (autogenerated):

### `GET /api/agent-proposals?where[status][equals]=pending&sort=-createdAt&limit=20`

**Auth**: admin/analytics-operator role.

**Returns**: `{ docs: AgentProposal[], totalDocs, ... }`.

### `POST /api/agent-proposals/{id}/approve`

**Auth**: admin/analytics-operator role.

**Body**:
```json
{
  "reviewerReason": "optional comment"
}
```

**Effect**:
- Validates `status === 'pending'`.
- Sets `status='approved'`, `reviewedBy=user`, `reviewedAt=now`.
- Triggers `afterChange` hook → enqueues execution.

**Response**:
- `200 OK` с обновлённым AgentProposal.
- `409 Conflict` если status уже не pending.
- `403 Forbidden` для readonly-roles.

### `POST /api/agent-proposals/{id}/reject`

**Body**:
```json
{
  "reviewerReason": "required ≤1000 chars"
}
```

**Effect**: sets `status='rejected'`, остальные fields аналогично approve. Активирует cooldown.

### `POST /api/agent-proposals/{id}/retry`

Только для `status='failed'`. **Не выполняет напрямую**: создаёт **новый** proposal с теми же payload + reasoning + `evaluator='manual_retry'` + `parentProposalId={id}`. Возвращает new proposal.

### `POST /api/agent-proposals/run-review`

**Auth**: admin only.

**Body**:
```json
{
  "period": "day" | "week",
  "date": "2026-05-26",            // optional, default yesterday
  "evaluators": ["funnel_drop_off", "drift_detector"]  // optional, default all
}
```

**Effect**: запускает agent-review on-demand (FR-376). Async — возвращает 202 Accepted с jobId; результаты появятся как новые AgentProposals.

**Используется**: admin-button «Run review now» + CLI `pnpm analytics:agent-review`.

## Admin UI (`/admin/agent-proposals`)

Payload Custom View с:

### List view

- Header: count badges «pending: N | approved: M | executed: K | failed: F | rejected: R».
- Filters: status (default 'pending'), evaluator, type, severity, date-range.
- Sort: createdAt DESC default.
- Each row: `[severity badge] | type | evaluator | summary | createdAt | actions`.
- Bulk actions: **none** (every proposal review individually — safety).

### Detail view

- **Header**: type + status badge + severity badge + created date.
- **Reasoning block** (expanded by default): LLM-generated explanation.
- **Evidence block**: data snapshot — usually table or chart (JSON-rendered).
- **Diff block**: для `drift_detected` и `update_*` — side-by-side current vs proposed.
- **Action buttons** (только если status='pending'):
  - **Approve** — primary green button. Optional reviewerReason field.
  - **Reject** — secondary red button. Required reviewerReason field (≤1000).
  - Для `drift_detected` — две кнопки: **Restore from config** / **Accept and update config** (вместо одной Approve).
  - Для `hard_delete` type — Approve button **серый**, требует второй click в modal-confirmation «Я понимаю, что это удалит историю».
- **Execution log** (если status executed/failed): timeline + raw response (collapsed).
- **Cooldown indicator** (если cooldownUntil > now): «Same proposal won't be created again until ...».

### Run review button

Top-right corner: «Run review now ▾» dropdown:
- Run daily review (last day)
- Run weekly review (last 7 days)
- Custom date range

Returns toast «Review запущен; результаты появятся через ~30 секунд». Refresh-button обновляет список.

## Execution worker

In-process queue (v1) с одним worker'ом. На approve:

```typescript
async function executeProposal(proposalId: string) {
  const proposal = await payload.findByID({ collection: 'agent-proposals', id: proposalId })
  if (proposal.status !== 'approved') return  // idempotency

  const client = createMetrikaManagementClient(...)

  try {
    const result = await applyProposalAction(client, proposal)  // dispatch by type
    await payload.update({
      collection: 'agent-proposals',
      id: proposalId,
      data: {
        status: 'executed',
        executedAt: new Date(),
        executionResult: result
      }
    })
  } catch (err) {
    await payload.update({
      collection: 'agent-proposals',
      id: proposalId,
      data: {
        status: 'failed',
        executionResult: { error: err.message, stack: err.stack }
      }
    })
    // alert admin via configured channel
  }
}
```

`applyProposalAction` — switch по `proposal.type`:
- `create_goal` → `client.createGoal(payload, { kind: 'proposal', proposalId })`.
- `update_goal` → `client.updateGoal(targetId, payload, ...)`.
- `soft_disable_goal` → `client.softDisableGoal(targetId, ...)`.
- `drift_detected` с action='restore' → series of API-calls для приведения в config.
- `drift_detected` с action='accept' → generate PR для metrika.config.ts (через git CLI или GitHub API в v1.1).

## Tests

Coverage: `apps/web/src/lib/analytics/agent/tests/proposals-workflow.test.ts`:
- Create proposal → status pending → cooldown set.
- Approve proposal → triggers execution → status=executed; AgentExecutionLog имеет proposal_id.
- Approve → API fails → status=failed; AgentExecutionLog имеет error.
- Reject proposal → status=rejected; cooldown активен; повторный evaluator не создаёт дубль.
- Duplicate evaluator run with cooldown active → 0 new proposals.
- Hard_delete type без confirmationFlag в payload → API-client отказывается.
