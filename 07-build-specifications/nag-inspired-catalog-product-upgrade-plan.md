# План Изменений По Каталогу И Карточке На Основе NAG

Дата: 2026-05-15.

## Цель

Использовать исследование PDU-раздела NAG, чтобы сделать каталог и карточку Soliton ближе к полноценному техническому интернет-магазину, но без усложнения MVP корзиной, оплатой и внешними интеграциями.

## Что Берем Из NAG

- Инженерные фасеты и счетчики товаров.
- В листинге: SKU, фото, цена, ключевые параметры, быстрый CTA.
- В карточке: первый экран с коммерческим блоком, документы, доставка/оплата, характеристики по группам.
- B2B-сценарий: счет, КП, документы, поставка по России, подбор по ТЗ.

## Что Не Берем В MVP

- Полноценную корзину.
- Онлайн-оплату.
- Реальные остатки по складам.
- Расчет доставки.
- Отзывы, вопросы и кредитование.

## Изменения В Реализации

1. Добавить вычисляемые товарные атрибуты из raw-данных:
   - тип изделия;
   - монтаж;
   - типы розеток;
   - количество розеток;
   - ток;
   - тип входа;
   - длина кабеля;
   - функции защиты/мониторинга;
   - коммерческие статусы: наличие уточняется, поставка по России, документы.

2. Обновить карточку товара в листинге:
   - фото;
   - SKU;
   - название;
   - параметры;
   - цена;
   - "Открыть";
   - "Запросить КП".

3. Обновить страницу товара:
   - коммерческая панель на первом экране;
   - сводка ключевых параметров;
   - структурированные группы характеристик;
   - документы;
   - доставка и оплата;
   - B2B-закупка;
   - похожие модели.

4. Оставить RFQ главным действием:
   - из листинга;
   - из карточки;
   - из категории.

## Acceptance Criteria

- Листинг товара показывает не только название, но и параметры выбора.
- В карточке есть блоки "Характеристики", "Документы", "Доставка и оплата", "Для юрлиц".
- Кнопка "Запросить КП" передает SKU и название товара.
- Проверки `pnpm lint`, `pnpm typecheck`, `pnpm build` проходят.
